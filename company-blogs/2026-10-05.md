## OpenAI

### [A model guide for the GPT-6 family](https://openai.com/index/practical-guide-building-gpt-6)
**公開:** 2026-10-02

GPT-6 ファミリーを使う開発者向けに、モデル選択、指示の書き方、長時間タスクの管理、本番運用の準備をまとめたガイドである。
モデルは最難関の推論向けの GPT-6 Astra、コーディングやコンピュータ操作向けの GPT-6.1 Sol、定型作業を大量に処理する GPT-6 Luna の 3 つで、推論レベル（Low から Max）と速度モード（Fast、Ultrafast）を組み合わせて選ぶ。
長時間タスク向けに、実行中に指示を差し込む mid-turn steering、ツールの完了を待たずに独立作業を続ける非同期ツール呼び出し、GPT-6.1 Sol のマルチエージェント（ベータ）が紹介されている。
推論レベルは会話の途中で変えてもキャッシュが壊れず、キャッシュ済み入力は最大 95% 安くなる。
プロンプト面では、AGENTS.md で安全な定型作業を明示的に許可し、「常に確認する」ではなく判断の境界を書くよう勧めている。

**読む価値:** GPT-6 世代で使えるエージェント向け API 機能と、それに合わせた指示の書き方を一度に把握できる。

## Hugging Face

### [The Agent Said It Was Done. The Database Disagreed.](https://huggingface.co/blog/microsoft/thinkingbox)
**公開:** 2026-10-03

Microsoft と Hugging Face が、エージェントを最終的なバックエンドの状態と副作用で採点するベンチマーク ThinkingBox を紹介している。
5 つの業務ドメインにわたる 507 のステートフルなワークフローを、18 モデルでそれぞれ 20 回ずつ実行し、pass@1、pass@20、20 回すべて成功したタスク数を報告する。
12 モデルの約 12 万試行の分析では、失敗の 67.24% がツールエラーなく正常終了しており、ツール呼び出しや最終応答だけでは失敗を見抜けないことを示している。
pass@1 の首位は 67.16% の Claude Opus 5.5 である一方、20 回すべて成功したタスク数は Claude Opus 5 と同じ 241 件だった。
Kimi-K3 は 1 回でも解けたタスクの割合で 93.89% と最も広く、毎回成功したのは 13.41% にとどまる。
到達範囲と一貫性は一致しない。

**読む価値:** 実データを書き換えるエージェントのモデル選定で、単発の正答率ではなく反復時の一貫性を見るべき根拠が数字で示されている。

### [Open-sourcing AstaBrief, the fast report-generation model in Asta](https://huggingface.co/blog/allenai/astabrief)
**公開:** 2026-10-02

Ai2 が、研究上の問いと検索した文献の抜粋から引用付きレポートを生成する 8B モデル AstaBrief を、学習データとともに公開した。
Qwen3-8B をベースに、数万件の実際の研究クエリ、引用を重視したフィルタリング、選好データで事後学習している。
さらにレポートを節ごとではなく 1 パスで書く生成パイプラインに変え、これらにより Asta 全体では Fast モードの生成時間が平均 51.1 秒になり、Claude を使う Thinking モードの 178.5 秒より約 3.5 倍速い。
学習と評価の大半は 2025 年に行われており、現在のフロンティアモデルとは比較し直していないと明記している。

**読む価値:** 小型のオープンモデルを特定タスクに事後学習して、商用モデルの代わりに使えるかを検証した具体例になる。

## Cloudflare

### [8 major updates to Cloudflare Observability](https://blog.cloudflare.com/one-observability-platform/)
**公開:** 2026-10-02 | **著者:** Sahidya Devadoss

ログ、トレース、分析、アラート、ダッシュボード、エクスポートを 1 つのオブザーバビリティ基盤にまとめる 8 つの更新を発表した。
Workers Observability と Log Explorer を統合した Logs では、HTTP イベント、ファイアウォール、Workers、R2、AI Gateway などのデータセットを同じ操作で SQL 検索できる。
全データを 1 つの SQL 方言と認証で扱う統一 SQL API（ベータ）は、cf CLI、Observability MCP サーバー、Workers のネイティブバインディングから使える。
2026 年 12 月 1 日から、ログとトレースの料金はイベント数ではなく取り込み量と保存量で決まる体系へ統一される。
ほかに Cloudflare Traces のオープンベータ、SQL で条件を書けるカスタムアラート、30 日保持のドメイン分析、セルフサーブプランでの Logpush 提供が含まれる。

**読む価値:** 製品ごとに分かれていた Cloudflare の観測データが統合される方向性と、今回使えるようになった機能を把握できる。

### [Streamline: custom video pipelines with Cloudflare Stream and Workers](https://blog.cloudflare.com/streamline/)
**公開:** 2026-10-02 | **著者:** Taylor Smith

Cloudflare Stream の映像に字幕の焼き込みや動的な注釈を加えるためのカスタム映像パイプラインの開発用プレイグラウンド Streamline を公開した。
Container 上で動く Media Engine（Go 製のコントローラと FFmpeg による処理部）と、それを制御する Workers のアプリケーションで構成される。
Media Engine は RTMPS のライブ入力や HLS の録画を入力に取り、処理結果を別のライブ入力や新しい録画として配信し、プレビューは Durable Object の WebSocket リレー経由で返す。
処理はリクエストのライフサイクルから切り離されており、Worker が切断されても続く。

**読む価値:** 長時間動くメディア処理をサーバーレス基盤上で組む際の、Containers と Durable Objects の役割分担の例になる。
