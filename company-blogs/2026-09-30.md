### [Highlights from Git 2.56](https://github.blog/open-source/git/highlights-from-git-2-56/)
**公開:** 2026-09-28 | **著者:** Elijah Newren

Git 2.56 の主な変更点の紹介。
`git add --resolved` は競合していたパスだけをステージし、競合マーカーが残っていれば何もステージせずに止まる。
merge base の探索では、片側だけから到達するコミットが尽きた時点で打ち切るようにし、大規模モノレポで約 20〜70 倍速くなった。
path-walk repack が reachability bitmap と delta island に対応し、ホスティング側で約 71%小さい pack を試せるようになった。
ほかに `git history drop`、`git refs` の create/update/delete/rename、`git branch --delete-merged` が追加された。

**読む価値:** 日常のマージ作業と大規模リポジトリの運用の両方に効く改善がまとまっている。

### [Building a post-quantum certificate authority with Merkle Tree Certificates](https://blog.cloudflare.com/pq-ca-with-mtcs/)
**公開:** 2026-09-29 | **著者:** Mari Galicer

新設する CA で Merkle Tree Certificates（MTC）を発行し、2027 年初めに Chrome の Quantum-resistant Root Store への収録を目指すという発表。
PQ 署名は従来の約 40 倍の大きさがあり、TLS ハンドシェイクの署名 5 個と鍵 2 個をそのまま置き換えると、クライアントや CT ログの負担が大きすぎる。
MTC は証明書を追記専用の Merkle tree にまとめ、CA はツリーのルートだけに署名し、クライアントはハッシュ列の包含証明で検証する。
「発行したものを記録する」のではなく「記録することで発行する」設計で、透明性が運用の前提条件になる。
標準の MTC 発行は無料で提供する予定。

**読む価値:** PQ 移行で Web PKI の構造がどう変わるかを、仕組みから理解できる。

### [Helping personal agents shop more intelligently and reliably with Link](https://stripe.com/blog/helping-personal-agents-shop-more-intelligently-and-reliably-with-link)
**公開:** 2026-09-29

AI エージェントによる購買を支える Link のエージェント向けウォレットに、3 つの機能が加わった。
1 つ目の incremental authorization は、税や送料で最終価格が上がったときに、購入をやり直さず承認額だけを引き上げられる機能。
2 つ目として、3D Secure の認証が必要な場合や決済が拒否された場合に、エージェントが次に取るべき手順を返すようになった。
3 つ目として、消費者の許可を得たうえで取引履歴をもとに商品を推薦でき、対象の購入には誤購入時の購入保護が付く。
今後は予算の範囲内なら取引ごとの承認を省けるようにする支出制御を追加する予定で、Link 経由のエージェント購買は直近 1 か月で 38 倍に増えたという。

**読む価値:** エージェントに決済を任せるときに必要な承認と保護の仕組みが具体的にわかる。

## Airbnb

### [Personalization without user identity](https://medium.com/airbnb-engineering/personalization-without-user-identity-8e7891a1d486?source=rss----53c7c27702d5---4)
**公開:** 2026-09-29 | **著者:** Wei Jiang

ログインしていない利用者や初回訪問者に対して、個人の識別子を使わずにパーソナライズする Proximity Features の紹介。
IP から得た粗い位置情報で近隣の約 1,000 人を 1 つのバケットにまとめ、そのバケットの検索や予約の傾向を日次で集計して特徴量にする。
都市部は細かいタイルと IP ハッシュで分割し、過疎地はタイルを広げていく適応的なクラスタリングで、2023 年に作った分割を再クラスタリングなしで使い続けている。
特徴量の取得は soft dependency で、タイムアウトしてもリクエスト処理は止まらない。
トップページの AutoSuggest では、履歴のない利用者向けの固定の人気都市リストを、地域に合った候補へ置き換えた。

**読む価値:** プライバシー規制の下でコールドスタート問題を扱う特徴量設計の実例として参考になる。

## Dropbox

### [Evolving our calendar assistant Reclaim to be AI-native without starting over](https://dropbox.tech/machine-learning/evolving-calendar-assistant-reclaim-to-be-ai-native)
**公開:** 2026-09-29 | **著者:** Greg Unrein, Josh Jensen, Christopher Wildman

カレンダーアシスタント Reclaim に、既存のスケジューラを作り直さずに自然言語で操作するエージェントを組み込んだ事例。
利用者の直接操作、自動スケジューラ、エージェントの 3 者が、同じ Schedule Action を通って検証とコミットを行うため、ルールを一か所で管理できる。
エージェントのループとツールは汎用フレームワークを使わずに自前で実装した。
採用を検討したフレームワークがプロバイダーの API に追いついていなかったことを理由に挙げている。
変更はまず Preview Mode の一時的なカレンダーで確認できるようにし、そのために自動スケジューラを副作用のない純粋関数に書き直した。

**読む価値:** 既存製品にエージェントを後付けするとき、実行経路の共通化と変更前のプレビューをどう設計するかの参考になる。

## Vercel

### [Search trace spans from the Vercel CLI](https://vercel.com/changelog/search-trace-spans-from-the-vercel-cli)
**公開:** 2026-09-29 | **著者:** Darpan Kakadia

`vercel traces search` で、プロジェクトのトレーススパンをターミナルから検索できるようになった。
環境、ステータス、トレース ID などで絞り込め、`--query` では KQL のサブセットを使って `span.duration > 2000` のような条件も書ける。
`--json` を付けるとスパンごとに 1 行の JSON を出力するため、コーディングエージェントに調査を任せやすい。

**読む価値:** エージェントから本番環境のトレースを直接調べられる CLI として実用的。
