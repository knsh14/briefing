## The Pragmatic Engineer

### [The state of the tech industry in 2026](https://newsletter.pragmaticengineer.com/p/the-state-of-the-tech-industry-in)
**公開:** 2026-10-06 | **著者:** Gergely Orosz

LDX3 での基調講演をもとに、AI ラボ、スタートアップ、ビッグテックで過去 1 年に起きた変化をまとめた記事。
変化した点として、手でコードを書く人がほとんどいなくなったこと、5〜10 のエージェントを並列で動かす働き方が広がったこと、IDE の存在感が薄れたことなどを挙げる。
GitHub のデータでは、エージェントが作成した PR が 8 か月で 9 倍に増え、2026 年 8 月には人間が作成した PR を上回った。
Linear では 7 月以降、エージェントが作成した Issue が人間の作成数を超え、Factory AI では利用者の 83% がスキルを使っている（2 月から 2.5 倍）。
一方で、コードレビューの形骸化や品質と信頼性の低下が問題として挙がり、チームや計画の重要性は変わっていないとしている。

**読む価値:** エンジニアリング組織を率いる人は、エージェント時代の開発の変化を実データ付きで把握できる。

**公開:** 2026-10-05 | **著者:** Jack Clark

## Mitchell Hashimoto

### [A Terminal Protocol for Program Status (OSC 7501)](https://mitchellh.com/writing/program-status-osc7501)
**公開:** 2026-10-06

プログラムが自分の状態を端末に伝えるエスケープシーケンス OSC 7501（Program Status Protocol）の仕様を提案する記事。
状態は idle、working、done、blocked、error の 5 種類で、blocked には permission、question、auth の種別と、base64 で符号化したメッセージを付けられる。
複数のエージェントの状態をまとめて表示する「agentic inbox」系のツールは、画面やウィンドウタイトルをヒューリスティックに読むか、独自のソケット API を使っており、前者は Claude Code の表示が変わるたびにルールの修正が必要になると指摘する。
pty を使うので SSH やコンテナ越しでも動き、シェルスクリプトから数行で出力できる。
libghostty と Rex に実装済みで、Terraform、Claude Code、Codex、Homebrew でも十数行の概念実証を作ったという。

**読む価値:** 端末エミュレータや CLI ツール、エージェント管理ツールの開発者は、状態通知を標準化する具体的な仕様を検討できる。

## Martin Fowler

### [Fragments: October 4](https://martinfowler.com/fragments/2026-10-04.html)
**公開:** 2026-10-05 | **著者:** Martin Fowler

LLM を扱う仕事は、決定的なシステムを「作る」ことから推論するシステムを「育てる」ことへ移っており、バグを直したり部品を無効にしたりする簡単な手段がないと論じている。
元同僚 Ola Bini がエクアドルから国外退去させられたことや、DDD Europe での Eric Evans との対談動画も紹介している。
後半では、人間がコードを読む必要があるかという議論を取り上げる。
Sam Ruby の試算では、Rails で約 6 万トークンのアプリを C に変換すると約 400 万トークンになり、LLM にとっても高水準の表現を正とする意味があるという。
さらに、コードは機械への指示だけでなく問題領域の概念モデルも兼ねており、LLM の時代には後者の役割が重要になるという Unmesh Joshi の主張を引いている。

**読む価値:** AI 時代のソフトウェア設計を考える開発者は、コードの表現と可読性をめぐる複数の立場を比較できる。
