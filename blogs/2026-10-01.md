## The Pragmatic Engineer

### [Distributed databases with Peter Mattis](https://newsletter.pragmaticengineer.com/p/distributed-databases-with-peter)
**公開:** 2026-09-30 | **著者:** Gergely Orosz

Cockroach Labs の共同創業者で CTO の Peter Mattis を迎えたポッドキャスト回の要点まとめ。
Gmail の初期ストレージで B-tree がスレッドと未読数を管理していたことや、Colossus が Reed–Solomon 消失訂正符号でストレージのオーバーヘッドを 33% 減らしつつ冗長性を高めたことが語られる。
std::map を B-tree で、Go の map を Swiss Table で置き換えて高速化した経験や、合意形成に最低 3 レプリカが要る理由、Pebble に至る CockroachDB のストレージエンジンの変遷も扱う。
Peter はエージェントの進歩で精査の必要が減っており、アセンブリを見なくなったのと同じようにコードを見なくなると予測している。

**読む価値:** 分散データベースの設計判断と、熟練エンジニアが AI で生産性をどう変えたかを当事者の言葉で知ることができる。

### [Why has Shopify dropped React Native?](https://newsletter.pragmaticengineer.com/p/shopify-native-mobile)
**公開:** 2026-09-29 | **著者:** Gergely Orosz

Shopify がモバイル開発の方針を React Native からネイティブに戻した理由を追った記事。
2020 年の React Native 採用は、Android 版の投入が遅れる問題を避けるためで、Android 版の遅れで成長の波を逃した Clubhouse の例が引かれている。
5 年後も採用は成功とされていたが、AI がネイティブのモバイルコードもうまく書けるようになり、React Native が追加する抽象化の利点が薄れた。
Shop アプリは 12 週間でネイティブに書き直され、記事は Airbnb や Notion の前例、Kotlin Multiplatform という選択肢も比較している。

**読む価値:** モバイルの技術選定に関わる読者が、AI が技術選択の損得をどう変えるかを具体例で考えられる。

## Martin Fowler

### [Principles for effective slides](https://martinfowler.com/articles/never-send-slides/slide-principles.html)
**公開:** 2026-09-30 | **著者:** Martin Fowler

発表スライドの設計原則を説く連載の一編。
スライドは話し手を置き換えるものではなく、声で伝える内容を補う視覚チャネルであり、ビルドや遷移で情報を出す速さを制御できる点がインフォデッキとの違いだとする。
聴衆は話すより速く読めるので、文章の多いスライドは話の主導権を奪うと指摘し、1 枚の箇条書きスライドを 31 枚の視覚要素に分割する例を示している。
既定ではミニマリズムを貫き、各スナップショットで出す情報を最小にするよう勧めている。

**読む価値:** 社内外で発表する機会のあるエンジニアが、聴衆の認知負荷を管理するスライドの作り方を学べる。
