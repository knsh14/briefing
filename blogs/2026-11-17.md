### [llm 0.37.3](https://simonwillison.net/2026/Nov/16/llm/)
**公開:** 2026-11-16

LLM のバグ修正リリースで、主な目的は Homebrew の最新パッケージで起きた不具合への対応である。
Homebrew が同梱するようになった SQLite 3.54.1 の修正で、LLM のログ記録のコードが動かなくなった。
SQLite 3.54.0 では `select json_object('a', (select json_array(1)))` が `{"a":[1]}` を返したが、3.54.1 では `{"a":"[1]"}` を返す。
D. Richard Hipp によれば、サブクエリの `json_array()` はドキュメント上 JSON ではなく SQL のテキストを返すので、3.54.1 の挙動が正しい。
回避策として、サブクエリを `json()` で包む書き方を示している。

**読む価値:** SQLite の JSON 関数をサブクエリと組み合わせて使う開発者が、バージョンアップで挙動が変わる箇所を確認できる。

**公開:** 2026-11-11 | **著者:** Martin Fowler

筆者が AI エージェントで開発する組織の開発者 26 人に聞くと、AI が機能追加のたびに既存のテストも書き換えるため、テストを信頼していないという答えが返ってきた。
AI が書くテストは量が多く読みにくく、モックで実装に密結合し、正しさではなく現在の実装をなぞるだけになりやすい。
散文の仕様も量が多く曖昧で実行できないため、顧客の言葉で書いたブラックボックスのテストを、ドメインの専門家が読めるテスト DSL のデータとして表すことを提案している。
以前は高くついた DSL のパーサーや専用のテストランナーも、今は AI のおかげで安く作れるという。

**読む価値:** エージェントにテストまで書かせている開発チームが、人が守るべき契約をどこに置くかを考え直す材料になる。

### [Long-horizon agents and durable execution](https://martinfowler.com/articles/durable-execution-agents.html)
**公開:** 2026-11-10 | **著者:** Martin Fowler

人や外部システムとのやりとりを含み、数日から数週間かかる作業を自動化する長期エージェントと、それを障害から立ち直らせる durable execution というパターンを解説する記事である。
durable execution では、外部とやりとりする各ステップの結果をランタイムが記録し、障害の後に再実行すると完了済みのステップを飛ばして状態を記録から復元する。
例として、見積もりを取り、管理者に価格の承認を求め、発注して納品まで追う在庫補充エージェント Stock Replenisher を Python で示している。
エージェントは目標、ツール、状態、モデルの 4 要素からなるループで動く。
例では、価格の承認前には発注のツールを使えないようにするなど、重要な業務ルールをプロンプトではなくコードに置いている。

**読む価値:** 何週間も待ちを挟むエージェントを本番で動かす設計者が、障害からの復帰の仕組みをコードで理解できる。
